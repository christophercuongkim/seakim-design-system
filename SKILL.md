If the user invokes this skill without any other guidance, ask them what they want to build or design, ask some questions, and act as an expert designer who outputs HTML artifacts _or_ production code, depending on the need.

## Generated files — never edit, never create

Some files in this project carry a `GENERATED by …` header. They are built from a source
file by a script that runs outside this project, so **editing one has no effect and
creating one does harm**: the next regeneration overwrites your edit, silently, and until
then the outputs disagree with their source.

This has already cost two regressions — a whole group of chart tokens deleted, and the
house accent reverting from crimson to orange — because a generated file was edited to
the intended value while its source was left behind.

| Want to change | Edit this | Not this |
| --- | --- | --- |
| Any colour or ramp | `tokens/src/color.tokens.json` | `tokens/colors.css`, `tokens/theme-light.css`, `tokens/apps.css`, `tokens/generated/colors.ts`, `flutter/lib/src/tokens/palette.g.dart` |
| Any icon code point | `flutter/tool/phosphor_codepoints.json` | `flutter/lib/src/tokens/sk_icons.g.dart` |

**If a generated file looks missing or stale, do not write it.** Say which source you
changed and that the outputs need regenerating — someone runs `node tool/build-tokens.mjs`
where the toolchain lives. A missing generated file is never an invitation to recreate it.

The same applies to a generator that does not yet emit something you need: change
`tool/build-tokens.mjs` and say so, rather than hand-writing the output it would produce.
